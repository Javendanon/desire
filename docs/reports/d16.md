# D16: character sheets and tactical encounter panel

Features live in `src/features/characters` and `src/features/encounters`. They hold no city
identity: the encounter's place arrives as a parameter (`createDemoEncounter(place)`) and picks
arrive through a `PlaceSubscription`, so Waterdeep or another city plugs in from its host page.

**No page mounts them yet.** An earlier draft added `tactical.html` and
`content/maps/waterdeep/tactical.ts`. They were removed because they fall outside this card's
scope. Mounting `TacticalOverlay` over the map viewer is composition work for D15, which also owns
`TableDemo`/`SelectedSheet`.

## Behaviour

- **Opening from the map (designed, not yet exercised in a browser).** Clicking the marker of the encounter's place opens the panel; a row
  opens the sheet. A launcher button offers the same path by keyboard, because canvas markers
  cannot take focus. The overlay receives a place subscription and never holds the viewer.
- **Sheet.** A sheet counts as supplied when any record beyond identity exists (stats, state,
  details, concentration or any list). So a sheet that only has conditions still shows them, as the
  panel does. Attributes, HP, equipment, actions, spells, conditions, concentration, classes,
  resources and proficiencies, all from D04 contract records. Rule text shows its source, edition
  and verification. An entry from another edition withholds its text and says why.
- **Actions.** The contract records actions on creature templates only, so a character sheet
  explains why its list is empty.
- **Demo and confirmed data.** Every sheet and encounter carries `Provenance`, shown as a text mark
  and a word. The fixtures are `synthetic`, and so are the three demo rules added because the
  compendium has no concentration spell or timed condition yet.
- **Ionyth.** Only the name is confirmed (`docs/nivel20-api.md`), so that record is identity only:
  the sheet reports that nothing else was supplied and hides the rules edition. Its badge reads
  "Confirmed" with "the cited source confirms only the name", so it does not suggest a confirmed
  sheet. Contract-required
  fields on the record (edition, disposition, visibility) are placeholders and are not displayed.
- **Colour.** Side, current turn, status, disabled state and evidence are all written as text.

## Interaction scope

| Interaction | Scope | Shown as |
| --- | --- | --- |
| Next turn, HP ±1, dismiss condition, undo | This tab, lost on reload | "Local only" |
| Particle toggle | `localStorage`, or this tab if the browser refuses it or `getItem` throws | "This device" or "Local only", both from the start (`effectsScope`) and after a failed save |
| Viewing sheet data | No write path | "Read-only" |

**No interaction reaches the server.** D09 exposes no route for sheets, actor state or encounters,
so there is no campaign-persisted interaction yet. A new scope must be added with those routes.

## Automated rules

The panel lists these itself (`src/features/encounters/automation-notes.ts`). Each has a test in
`tests/character-sheet.test.ts` or `tests/encounter-state.test.ts`, and those tests pass:

- Ability modifier, total level (derived, never stored).
- Turn order, with ties stable and an unset initiative last. Unset initiatives take no turn.
- Round counter, and a one-round tick per round on timed conditions.
- Expiry: when a timed condition's last round elapses, it is withdrawn for the session. It is
  added to `dismissedConditions`, and 0 is never stored. This follows `docs/modelo-de-datos.md`
  ("Cero implica retirar condición en D16"), and `remaining_rounds` is a `Revision` with a minimum
  of 1 (`contracts/schema.json`).
- HP edits clamped between 0 and the recorded maximum.

Left to the table: dice, saving throws, damage, temporary HP, death and unconsciousness, ending a
condition early or one with no fixed duration, spell preparation, and anything on Nivel20.

The round tick is a tracker simplification: 5e durations can end on a specific creature's turn.

## Effects

`planParticles` caps the animated elements at `PARTICLE_BUDGET` (12). The plan is empty when the
toggle is off or the system requests reduced motion, and the layer is `aria-hidden`. Only
`transform` and `opacity` animate.

## Merge-candidate rework: the `rust-test` gate

Unix socket inside the cluster directory (`$PWD/.local/d08/pg.XXXXXX`), and a Unix socket path is
capped near 104 bytes. The candidate lives under a 92-character worktree
(`.../_merge/a5321cc1-...-1793986055`), so the full socket path measured 130 bytes and PostgreSQL
logged `could not create any Unix-domain sockets` before exiting. CI never shows it because

socket directory stops being a `/tmp` `mktemp` directory or stops being what the cluster binds.

## Pre-review rework: the header read the session view, not the record

The second independent pre-review (grok-4.7) found one HIGH in `CharacterSheet.svelte`. The sheet was
handed `openSheet = applyLocal(recordedSheet, local)`, and the header asked that view three
questions: whether the sheet was supplied (`hasSheetData`), which edition it used (`rulesLine`), and
what its evidence badge said (`sheetBadge`). `applyLocal` drops dismissed and expired conditions, so
a record whose only data is conditions looked empty after the last one was dismissed or its duration
ran out: the badge fell back to "only the name is confirmed", the edition line said it was not
confirmed, and the local-change note disappeared while the panel still listed the actor.

The fix keeps the session view for the rows, so dismissed conditions stay hidden, and passes the
record separately. `CharacterSheet` now takes `recordedSheet`; `sheetHeader(record)` in
`sheet-view.ts` returns the supplied flag, the edition line and the badge from it, and the component
makes one call to that helper. `TacticalOverlay` passes both sheets. Two tests in
`tests/character-sheet.test.ts` cover the gap: a conditions-only record probed with
`dismissCondition` and with round-end expiry, then `applyLocal`. Each asserts the view is empty
*and* that `sheetHeader` reads the record as supplied, with a confirmed edition and a full badge.

RED was observed as a module-load failure: before the fix `sheet-view.ts` had no `sheetHeader`
export, so the test file could not load. The stronger failure is not reachable without rendering a
Svelte component, which this repo's `node --test` setup cannot do; the behavioural assertions still
pin the invariant that the session view is empty while the record is supplied.

The reviewer also raised four non-blocking suspicions, left as documented debt: nothing mounts
`TacticalOverlay` (D15 owns mounting), `handleKey` does not check `defaultPrevented`, the local
state is initialised once with `untrack` and not reset if `bundle` changes, and the identity-only
Ionyth header still prints the placeholder kind. None is reachable through a path this card owns.

## Known limits

- The map has place markers but no miniatures, so a sheet opens from the panel, not a token.
- `TableDemo` and `SelectedSheet` (D03) are not wired to these features. D15 owns composition.
- The client does not filter `visibility: dm`: it labels it. Authorised projection is server work
  (D09/D10) and DM features are D17.
- Knowledge lookups use the bundled compendium, because no compendium HTTP route exists.
