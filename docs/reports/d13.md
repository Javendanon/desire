## How it works

- **Chunks:** 435 sectors of 250 m. The focus sector is always resident; the nearest sectors by
  centre distance get detail.
- **Load/unload:** walls and roofs are built per sector when its detail level changes and its
  instance buffers are freed when it leaves the resident set.
- **Instancing:** one instanced box batch per stone/timber wall set and one per roof tone per
  sector; the whole city far shell is a handful of instanced batches.
- **LOD:** 0 = far shell only, 1 = walls + flat roof, 2 = walls + gable roof. Thresholds are
  160 m / 420 m from the focus, with a cap of 20 detail sectors.
- **No gaps:** the far shell is always drawn, the ground mesh is generated from land spans, and
  resident sectors are added on top of their smaller far copies.
- **Selection:** place markers carry D05 positions and a stable D04 UUID plus a `waterdeep:<slug>`
  catalog key; pointer picking uses spheres that follow the marker scale.

## Coverage, limits and pending work

- Measured: TypeScript/TSX-adjacent sources and the new HTML page with `km`, the project gate,
  Node tests, `svelte-check`, `tsc`, Vite build and Rust tests.
- Not measured: Markdown, JSON, the Svelte template/CSS beyond the gate's text heuristics, and GPU
  memory with a profiler. `matrixBytes` is an allocation estimate, not a driver reading.
- The browser smoke ran on headless Chrome with WebGL 2. WebGPU was not exercised in this session.
- `waterdeep.html` is a Vite dev entry like `engine-smoke.html`; it is not part of `pnpm build`
  outputs. Adding it to the production build belongs to the integration card that composes routes.
- Lore text is not present: places carry a stable catalog key and D04 record, but the knowledge
  import (D07) owns the text. This is a deliberate dependency, not a hidden fallback.
- Street anchors are points, not a street graph; ward boxes are calibration aids, not boundaries;
  the shoreline and harbour are labelled interpretations. No building height is claimed as source.
- The far shell is always resident, so its matrix buffer scales with the number of lots. Splitting
  the far shell itself is the next memory step if the city grows.
- The D11 test viewer and the new map viewer are separate entry points; no regression was observed
  in the existing engine tests or smoke paths, but the D11 browser smoke was not rerun here.
