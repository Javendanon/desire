## What changed

- `crates/api/src/lib.rs`, `main.rs`: app state, routing bootstrap, `DATABASE_URL`
  connection, loopback guard for the development identity header, `--migrate` mode.
  A plain `fn main` connects and migrates before building the server runtime, and the
  state stays owned by `main`, so the blocking client is never created or dropped from
  inside a runtime.
- `crates/api/src/db.rs`: one blocking client behind a mutex, with the startup settings
  retained. Every request pings the socket and replaces a closed client, so a database
  restart costs at most the request already in flight.
- `crates/api/src/access.rs`: membership/DM/owner checks. Non-members receive 404.
- `crates/api/src/error.rs`: one error response using the D04 `transport::ApiError`
  DTO; SQLSTATE mapping; delete conflicts become `resource_in_use`; key reuse becomes
  `idempotency_conflict`; NUL-character SQLSTATEs map to 400.
- `crates/api/src/extract.rs`: `Caller` (`x-desire-user`, request id, optional
  `Idempotency-Key`), `ApiJson` and `ApiQuery`, all with one failure shape.
- `crates/api/src/validation.rs`, `payloads.rs`, `query.rs`, `ids.rs`: UUID, text
  (blank, length and NUL), revision and provenance validation; bounded `limit`/`offset`;
  generated request ids.
- `crates/api/src/routes/`: campaigns, members, sessions, scenes, characters, journal,
  knowledge. Shared list/get/create/update/delete scaffolding is generated by macros;
  handlers contain no SQL.
- `crates/api/src/store/`: the only SQL layer. Campaign create/read/rename, scene
  writes, session and note creation reuse D08 repositories. Missing D08 operations are
  implemented here with campaign-scoped SQL.
- `crates/persistence/src/scenes.rs`: `SceneRepository::replay` returns the scene and
  event a key already stored, so a scene-creation retry replays the first result.
- `crates/api/tests/`: 30 HTTP integration tests and 5 unit tests, against real
  migrations and real PostgreSQL, including one that starts the compiled binary.
- `src/lib/api/client.ts`, `src/lib/api/campaigns.ts`: typed frontend client. Every
  request type derives from `src/generated/contracts.ts`; the hand-written draft
  interfaces are gone, and sessions, `getJournal` and `getKnowledge` were added.
- `tests/api-client.test.ts`: 7 client tests (paths, headers, idempotency, errors,
  character patch shape, generated session/journal/knowledge shapes).
- `docs/api/campaigns.md`: endpoints, roles, pagination, limits, error shape, sanitized
  examples and known gaps.
- `tools/quality/quality/evaluate.py`, `tools/quality/known-false-positives.json`: F9
  findings now quote the duplicated run, and the import-header group of the sibling
  route modules is documented as a false positive.

## Behavioral coverage

- Authorized operations per resource: campaigns create/read/rename, members add/list/remove,
  scenes list/create/read/update, sessions list/create, characters and journal and
  knowledge create/read/update/delete. Campaigns and scenes have no delete in v1, by
  decision; the reasons are in `docs/api/campaigns.md` under known gaps.
- Missing resources: GET, PATCH and DELETE paths return 404; stale revisions return 409;
  duplicate membership, owner removal and removing a controller return 409; unauthorized
  role changes and player writes return 403.
- Invalid input: malformed UUIDs, blank names, unknown fields, bad enums, invalid
  `Idempotency-Key`, NUL characters, and `limit`/`offset` bounds (including non-numeric
  and negative values) return 400 with the shared error DTO and a request id.
- Campaign isolation: lists only include memberships; non-members and another
  campaign's DM get 404 on GET, PATCH and DELETE for every resource; the row is
  unchanged afterwards; players cannot write and only see player-visible rows, with
  hidden notes, knowledge and NPCs returning 404.
- Scene writes use the D08 outbox/idempotency path: identical retries replay the first
  result with one outbox row, a different body under the same key returns
  `idempotency_conflict`.
- Character creation rejects a controller outside the campaign; assigning or clearing a
  controller keeps the trigger-created actor row in step; delete removes actor rows in
  one transaction and conflicts if referenced.
- Sessions are created by DMs, listed by members, and journals reject a session from
  another campaign.

## Debt and blockers

- D10 authentication: `x-desire-user` is a development seam. The server refuses a
  non-loopback bind unless `DESIRE_DEV_IDENTITY=1`; it must not be exposed before D10.
- D17 visibility: this API filters DM rows and returns 404 for hidden entries as a
  safe default; the final player projection belongs to D17.
- Scene deletion needs a soft-delete/archive migration; v1 has no route instead of one
  that always answers 409.
- One blocking client behind a mutex, plus one `SELECT 1` per request, serializes and
  doubles the round trips. Replace with a pool when concurrent throughput matters.
- `km` gate scope with multiple `--include-ext` flags does not report Rust
  parameter/long-function smells (verified by comparing the gate scope with a focused
  `km smells crates/api`). The focused run was used for the floor/target numbers above;
  this is a D02 tooling limitation, not an API exemption.
- The single F9 critical duplication group in `crates/api` is the import header shared
  by three sibling route modules. It is recorded in
  `tools/quality/known-false-positives.json` with its justification; the gate keeps
  reporting it in the JSON output as suppressed so it stays visible.
- No line/branch coverage was measured.
