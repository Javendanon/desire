## What changed

- `crates/api/src/lib.rs`, `main.rs`: app state, routing bootstrap, `DATABASE_URL`
  connection, loopback guard for the development identity header.
- `crates/api/src/access.rs`: membership/DM/owner checks. Non-members receive 404.
- `crates/api/src/error.rs`: one error response using the D04 `transport::ApiError`
  DTO; SQLSTATE mapping; delete conflicts become `resource_in_use`.
- `crates/api/src/extract.rs`: `Caller` (`x-desire-user`, request id, optional
  `Idempotency-Key`) and `ApiJson`, with one failure shape.
- `crates/api/src/validation.rs`, `payloads.rs`, `query.rs`, `ids.rs`: UUID, text,
  revision, provenance validation; bounded `limit`/`offset`; generated request ids.
- `crates/api/src/routes/`: campaigns, members, scenes, characters, journal,
  knowledge. Shared list/get/create/update/delete scaffolding is generated by macros;
  handlers contain no SQL.
- `crates/api/src/store/`: the only SQL layer. Campaign create/read/rename, scene
  writes and note creation reuse D08 repositories. Missing D08 operations
  (campaign list, members, scene list, character CRUD, DM note reads, note
  update/delete) are implemented here with campaign-scoped SQL.
- `crates/api/tests/`: 18 HTTP integration tests against real migrations and real
  PostgreSQL, plus contract-shape assertions.
- `src/lib/api/client.ts`, `src/lib/api/campaigns.ts`: typed frontend client. Request
  types derive from `src/generated/contracts.ts` with `Omit`, so the client cannot
  drift from the D04 schema.
- `tests/api-client.test.ts`: 8 client tests (paths, headers, idempotency, errors,
  character patch shape).
- `docs/api/campaigns.md`: endpoints, roles, pagination, limits, error shape,
  sanitized example and known gaps.

## Behavioral coverage

- Authorized create/read/update/delete for campaigns, members, scenes, characters,
  journal and knowledge.
- Missing resources: GET and PATCH paths return 404; stale revisions return 409;
  duplicate membership and owner removal return 409; unauthorized role changes 403.
- Invalid input: malformed UUIDs, blank names, unknown fields, bad enums, invalid
  `Idempotency-Key`, and `limit`/`offset` bounds return 400 with the shared error DTO.
- Campaign isolation: lists only include memberships; cross-campaign reads and writes
  return 404; player journal/knowledge lists hide `dm` rows and direct reads 404.
- Character creation rejects a controller outside the campaign; delete removes the
  trigger-created actor row in one transaction and conflicts if referenced.
- Scene writes use the D08 outbox/idempotency path; hard delete is a documented 409
  while outbox history references the scene.

## Advisor

An independent `pi` reviewer (separate process, read-only) reviewed the working tree
three times. Findings and resolution:

1. Leftover DB debug `eprintln` in `error.rs`: removed before commit.
2. Updates of missing rows returned 409 from D08 CAS paths: added existence reads
   before scene update and campaign rename; added `updates_of_missing_resources_return_not_found`.
3. Frontend `PatchCharacter` included immutable `rules_edition` while the backend
   patch rejects it: changed to `Omit<NewCharacter, 'rules_edition'>` and added a
   client test that the field is absent.
4. Final review verdict: PASS, after comparing every frontend request type with the
   backend payload and re-running the focused checks.

The advisor also noted that `access::owner_id` holds one authorization query outside
`store`, and that campaign creation has no explicit access call because any
authenticated caller may create their own campaign. Both are intentional and
documented here rather than hidden.

## Debt and blockers

- D10 authentication: `x-desire-user` is a development seam. The server refuses a
  non-loopback bind unless `DESIRE_DEV_IDENTITY=1`; it must not be exposed before D10.
- D17 visibility: this API filters `dm` rows and returns 404 for hidden entries as a
  safe default; the final player projection belongs to D17.
- D08 gaps: no session endpoint (journal tests seed sessions), no membership role
  update, scene hard delete blocked by outbox history, and character hard delete
  blocked when sheets/conditions/encounters reference the actor.
- One blocking `postgres::Client` behind a mutex serializes requests. Add a pool when
  concurrent throughput matters.
- `km` gate scope with multiple `--include-ext` flags does not report Rust
  parameter/long-function smells (verified by comparing the gate scope with a focused
  `km smells crates/api`). The focused run was used for the floor/target numbers above;
  this is a D02 tooling limitation, not an API exemption.
- No line/branch coverage was measured.
