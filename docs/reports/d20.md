## Scope

An optional entry sequence before a campaign, behind the `campaign_prologue` runtime flag (off by
default). It adapts the vendored MIT Scroll World resource as a stills-only scroll prologue: the
existing illustration, three framings, no generated footage, no paid services, no change to the 3D
engine or the table. The table stays mounted behind the prologue and works whether or not the
prologue renders.

## Findings during the work

- The first browser run failed at the slow-network step: throttling the whole page also throttles the
  application bundle, so the prologue never mounted within the wait. The step was replaced by a
  blocked-illustration step, which tests the same requirement (usable entry while the scene asset is
  missing) without timing out on the bundle.
- The first `svelte-check` run warned that `<section role="dialog">` is not allowed; the overlay is a
  `<div role="dialog" aria-modal="true">`.
- `km` flagged two semicolons inside comments as "multiple statements on one line" (F16) and one
  `toFixed(3)` literal as a magic number. The comments were reworded and the literal named
  (`SCALE_DECIMALS`).

Known limits:

- One illustration in three framings. There is no clip, so no video scrubbing, no mobile decode
  measurement and no FPS claim; adding clips requires object URLs and therefore an explicit
  `URL.revokeObjectURL` path in `destroy()`.
- Scene geometry is recomputed on each `scroll` event, so a viewport resize with no scroll keeps the
  previous drift until the next scroll (`ponytail:` note at `scroll-prologue.ts:69`).
- `prefers-reduced-motion` is read once when the prologue mounts; toggling the OS setting while it is
  open changes nothing until the next campaign entry.
- The prologue is offered once per page load and is not persisted as a preference.
- All three beats stay in the accessibility tree while they cross-fade; for a linear intro the
  reading order is the sequence order.
