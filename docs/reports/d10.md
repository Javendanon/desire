## What changed

- `crates/api/src/auth/`: password derivation (PBKDF2-HMAC-SHA256, 600k iterations,
  16-byte salt), bounded credentials, session lookup and the four auth routes.
  Only the SHA-256 digest of a 32-byte random token is stored.
- `crates/api/src/extract.rs`: bearer extraction, request id, optional `Idempotency-Key`.
  The legacy `x-desire-user` header remains a test/local seam.
- `crates/api/src/access.rs`, `crates/api/src/store/`: membership is the authorization
  source. Player projections and DM-only rows are filtered in SQL before serialization;
  `private.dm_secrets` never enters a snapshot or an event.
- `crates/api/src/store/sync.rs`, `crates/api/src/routes/sync.rs`: cursor-based
  `GET /api/v1/campaigns/{id}/sync`. Without `after` it returns a bounded snapshot; with
  `after` it replays ordered `scene_changed` events, falls back to a snapshot on a gap,
  and returns an empty batch when the cursor is current.
- `crates/persistence/src/realtime.rs`, `crates/persistence/src/identity.rs`,
  `migrations/0012_identity.sql`: identity tables, campaign stream revision and the
  public outbox. A scene write advances the stream and inserts its event in one
  transaction; campaign, character, journal and knowledge writes advance the stream
  without an outbox row. Snapshot rows and the cursor share one repeatable-read
  transaction.
- `crates/core/src/contracts/transport.rs`, `contracts/schema.json`,
  `src/generated/contracts.ts`: auth and sync transport DTOs, generated from the shared
  schema.
- `docs/api/auth-realtime.md`: protocol, permission matrix, threat model and open limits.
- `README.md`: bearer requirement and the loopback-only development header.

## Threats and limits

The security boundary, the threat table and the remaining limits are in
[docs/api/auth-realtime.md](../api/auth-realtime.md). The main open limits are: no login
or registration rate limiting, no token rotation or per-device revocation, no outbox
retention job, no automatic merge of concurrent edits (the losing writer retries), and
TLS termination is an operator responsibility.

No real password, token, Nivel20 credential or secret is stored in documentation,
fixtures, logs or commits. The examples use synthetic values only.
