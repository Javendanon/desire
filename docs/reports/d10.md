## Scope and plan

The approved redesign replaces passwords with Google OpenID Connect. Risk: HIGH,
because all protected routes depend on caller extraction. D15 consumes identity;
D04 owns the shared contract source. Only D10 auth transport changes:
`AuthIdentity.email` replaces username and the token-returning `AuthSession` is
removed. No domain DTO, protocol version or existing realtime writer changes.

The plan was: measure the existing test/gate baseline; add a failing OIDC entry-point
check; replace account storage with `(issuer, subject)`; delegate OIDC to the
required library; issue hashed opaque cookie sessions; enforce Origin on mutations;
exercise local signing-provider failures and preserve authorization/cursor tests;
run gates, independent review and commit on the existing branch. No parallel service
or frontend login screen was added.

## Changes

- `crates/api/src/auth/`: `openidconnect` discovery/JWKS, Authorization Code with
  S256 PKCE/state/nonce, library ID-token verification, verified-email admission,
  environment validation, browser-bound single-use flows, opaque cookie sessions
  and same-public-Origin mutation protection. Password and credential modules are
  deleted. Provider tokens never reach JavaScript or persistence.
- `crates/api/src/extract.rs`: production identity comes from the session cookie,
  not a bearer token or a caller-supplied account ID. Ambiguous/malformed cookies
  fail closed. Authenticated sessions never fall back to the development header.
- `crates/api/src/main.rs`, `lib.rs`, `routes/mod.rs`: OIDC initialization before
  listening, non-loopback startup refusal without OIDC, new login/callback routes,
  no-store on all API responses, including authentication failures. The header seam requires opt-in and a
  loopback bind. Without OIDC, browser development additionally requires an explicit
  loopback `DESIRE_PUBLIC_URL`; production cookie-Origin checks are not relaxed.
- `migrations/0013_identity.sql`, `crates/persistence/src/identity.rs`: no password
  column; unique `(issuer, subject)` with display-only email. Atomic account upsert
  and session issuance converge under concurrent callbacks. Session tokens are
  SHA-256 digests with 12-hour expiry; logout deletes the row.
- `contracts/schema.json` and generated Rust/TypeScript: identity DTO updated from
  the shared source. `src/lib/api/` exposes typed login navigation, identity,
  logout and campaign sync; requests send same-origin cookies without requiring a
  development identity. D15 still owns the screen and polling lifecycle.
- `crates/api/tests/`: local discovery, JWKS, runtime-generated RSA signing keys,
  single-use PKCE code endpoint and browser-shaped redirect checks. The real-binary
  authorization/default-bind regression now uses cookie sessions.
- `docs/api/auth-realtime.md`, `docs/api/campaigns.md`, `README.md`: Google Cloud Web-client setup, domain
  and localhost callback URIs, all five OIDC environment settings, secure-cookie
  deployment requirements and updated threats.

The old password migration was not in main. An existing database initialized from
that branch must be recreated; the migration runner correctly rejects edited
migration history. No existing database or service was modified for this rework.

### Security re-audit follow-up (network budgets)

The offline security re-audit reproduced one remaining lockout: 128 addresses from one
IPv6 /64 (or 128 spoofed values of a trusted header the proxy does not overwrite) filled
the 1024-flow pool, and an unrelated client then received `503 oidc_busy`.
`crates/api/src/auth/oidc.rs` now applies nested network budgets: eight flows per IPv4
address or IPv6 /64, and 64 per IPv4 /24 or IPv6 /48. Filling the pool needs at least 16

leaving the pool open. `tests/login_admission.rs` sends 1024 logins rotating inside one

global-cap test now spreads its clients over separate /24 networks.
