## What was delivered

An offline, zero-dependency Node pipeline that turns a calibrated illustration manifest into a
navigable glTF 2.0 binary plus an acceptance report:

- `tools/assets/src/manifest.js`, `heights.js`, `values.js` — strict manifest validation,
  including the height evidence policy that keeps interpretation from becoming measurement.
- `calibration.js` — D04 transform (x east, z south, y never inferred) and scale-check
  arithmetic; the ground rectangle follows the same transform, so a pixel origin shifts ground
  and anchors together.
- `scene.js`, `geometry.js`, `glb.js` — metric scene and glTF binary with render LOD0 per place,
  a merged LOD1 and a separate, material-less `collision` node.
- `gltf-read.js`, `check.js`, `nav.js`, `textures.js` — checks that read the written artifact:
  accessor layout, collision coverage, compressed-texture magic bytes and budgets, and a
  conservative grid flood fill from the spawn to every waypoint.
- `pipeline.js`, `asset-pipeline.js` — build orchestration, report writing and artifact
  quarantine: a failing build keeps no `.glb` and renames a previous one to `.stale`.
- `samples/sample-harbor/` — synthetic 10-place scene (8 solids, 2 unknown heights), a 52-byte
  WebP texture, the generated 30 KB `.glb` and its `report.json`. The label states it is
  not Waterdeep cartography.
- `docs/asset-pipeline.md` — tool evaluation, decisions, acceptance mapping and limits.

Not touched: runtime viewer (D11), Waterdeep content (D13), Rust crates, `package.json`,
Compose, Nivel20. No network calls, no paid service, no third-party artwork.

## Independent review

Two rounds with a separate agent in a clean context (`pi -p`, read-only, different model than
the author's session).

Round 1 on `5ed7807` raised 14 findings. The blocking one was real: `ground` pushed four color
floats while `COLOR_0` was declared `VEC3`, producing `count: 5.333…` in the artifact, so the
"glTF 2.0" claim was wrong. It also found that collision coverage only checked "non-empty",
that anchors were not bounded to the frame or ground, that rotation moved anchors but not the
grid, that malformed manifests crashed instead of reporting, and that a failing build could
leave a stale `.glb`.

Round 2 on `3f94bec` confirmed fixes 1–5, 7, 8 and 11 as fixed with mutation evidence, and
identified residuals: origin offsets could still put a solid off its ground, a missing
`textures` section passed validation and crashed, null/malformed entries still threw, the
texture budget branch was untested, a stale artifact survived a failing rebuild, and two NITs.

All residuals were fixed after round 2 and re-checked with the reviewer's own reproductions:

| Residual | Fix | Evidence |
| --- | --- | --- |
| Origin offset put solids off the ground | `planGround` shifts ground with the anchors | `/tmp` manifest with origin (256,192): PASS, nav origin (−64,−48), waypoint reachable |
| Missing `textures` section | required array in validation | test + exit 2 with `textures must be an array` |
| Malformed entries threw | per-entry guards and a validator try/catch | `materials:{}`, `textures:{}`, `places:[null]`, `scale_checks:[null]`, string color: exit 2, report written, no artifact |
| Texture budget untested | `checkTextures` budget test | 52-byte file with a 10-byte budget fails |
| Stale artifact after a failing rebuild | rename to `scene-<id>.glb.stale` | pipeline test asserts no `*.glb` and one `*.stale` |
| Accessor check type-blind | attribute and index type checks | fabricated `COLOR_0: VEC4` and non-SCALAR indices fail |

Mutation spot-checks: reverting the RGB reduction fails the accessor test; stubbing
`uncoveredSolids` to `[]` fails the coverage test; dropping the budget comparison fails the
budget test.

## Coverage and blockers

- `km` does not type-check or lint JavaScript; `tsconfig.json` covers `src/**` only. F13 for
  `tools/assets` rests on runtime validation and tests. A `checkJs` target belongs to D02.
- No external glTF validator or browser consumer was available offline. The artifact is checked
  by the local reader and its tests against the glTF 2.0 rules that bit us in round 1; a
  standards validator should be added with a vendored binary (D02/D21).
- `package.json` has no `test:assets` script: manifests belong to D01. The commands are
  documented instead.
- D04, D05 and D11 live on their own branches and are not merged into this worktree. The manifest
  reuses D04's `Calibration` shape and D05's provenance style; wiring the real Waterdeep
  calibration is a content change for D13, not a code change here.
- Splats, decimation and texture KTX2 encoding are deferred with stated conditions; LOD1 is
  currently a draw-call LOD and the report says so instead of claiming triangle savings.
- Rotation is rejected rather than half-implemented; the limitation is documented with the
  upgrade path (rotate ground, collision and grid together).
- A build killed mid-flight can leave one `.pending` file; the next build removes it. Not tested.
- The GLB in `samples/` is a regenerable artifact committed as acceptance evidence. Rebuilding
  the sample reproduces the same bytes.

## Claim

For the `tools/assets` scope, the floor and the objective both hold (A+ 93.9, 0 smells, max
complexity 9). The sample scene is navigable with separated collision, validated scale,
compressed texture, recorded provenance and explicit fidelity marks. This is not a claim that
the whole project passes a gate: Svelte/HTML coverage and the dependency-blocked Rust tests
belong to other cards, and the vendored engine still caps the whole-tree score.
