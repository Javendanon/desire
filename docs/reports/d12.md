The largest input contains 1,048,576 cells and 4,194,304 bytes.
The browser verifies actual buffer detachment after transfer. The 64×64 output
contains 127 points, or 1,016 logical coordinate bytes. The largest open-grid
route contains 2,047 points, or 16,376 logical coordinate bytes. JS array and
structured-clone overhead are not represented by these logical sizes.

Cross-context clocks round independently. Raw outbound samples include values
near -0.10 ms. Treat sub-0.2 ms transfer differences as clock uncertainty,
not negative latency. Computation and end-to-end durations use same-context clocks.

A repeat after rebuilding Wasm passed again: 130.3 ms pending, 13 trusted clicks,
4 frames and a 50 ms maximum frame gap (`outputs/d12-browser-final.json`).
This check proves interaction, not a sustained 60 fps budget.

Rework 3 reran the full browser check five times after the merge
(`outputs/d12-browser-rework3-{1..5}.json`), all passing: 96.3–102.2 ms
pending, 9–10 trusted clicks, 6 frames, 16.8 ms maximum frame gap. First
requests took 8.9–43.9 ms. Warm requests stayed at 0.4–1.9 ms, so the
35–45 ms warm samples of the earlier run did not reproduce. Their cause is not
isolated; main-thread contention from the 10 ms synthetic click stream or GC
are plausible. D14 should treat warm latency as usually about 1 ms with a
tail of tens of milliseconds, not as a fixed figure.

Native reference (`cargo run --release -p desire-core --example routing_benchmark`,
`outputs/d12-native-benchmark.txt`): 256×256 open grid, 511-point path, cost 510,
0.081 ms average over 20 searches. That is native Rust, not Wasm in a browser.

These samples compare complete worker requests with the existing TS reference.
They do not prove a general Wasm speedup: Rust uses A*, while the reference uses
quadratic Dijkstra. Cold startup can erase the short-route advantage.
The isolated page proves interaction during calculation, not D14's final UI or
GPU performance. The worker does not address GPU saturation.

IDs. No test-only production seam is added.

## Remaining limits

- No worker watchdog. A worker that exits without an error event can leave a request pending.
- `pnpm build` needs wasm-pack and the Wasm target; `pnpm check` and CI do not.
- Synchronous search cancellation terminates the worker. Restart cost remains visible in cold timings.
- The maximum grid is a resource bound, not a guaranteed frame-time budget for every device.
- D14 owns final UI integration, travel authorization and conversion from cells to calibrated world units.
