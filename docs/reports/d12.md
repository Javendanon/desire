## Delivered

- `crates/core/src/routing/`: typed `Grid`, `Cell`, `RouteRequest`,
  `RoutePlan`, `RoutingError` and deterministic A* over four-neighbour cells.
  Costs are non-negative `u32`; `0xFFFF_FFFF` is an obstacle; zero-cost cells
  are valid; total cost is bounded by the `u32` transfer contract.
- `crates/wasm/src/lib.rs`: `RoutingGrid`, `GridPoint`, `RouteSpan`,
  `RouteIdentity` and `RouteOutcome`. Input costs copy into Wasm once; the path
  copies out once; the grid is freed per request. No Wasm view is retained.
- `src/lib/routing/`: worker protocol, client, pure outcome mapping and
  dedicated worker. A new request terminates an in-flight worker and reuses an
  idle one; `cancel()` terminates. Results are accepted only for the latest
  `requestId` plus map `revision`.
- `tests/routing-worker.test.ts`: stale result, cancellation, duplicate,
  malformed message/response, worker failure, invalid-grid rejection,
  buffer-copy and outcome-mapping tests.
- `tools/routing/reference.ts` and `tools/routing/compare-reference.ts`:
  independent TypeScript Dijkstra used to compare route cost with the Rust core.
- `docs/routing-contract.md`: contract for D14, including units, copies,
  cancellation, errors, revision rules and non-goals.

## Baselines and limits

- The `@ts-ignore` on the generated Wasm import is build-order debt: the module
  only exists after `pnpm build:wasm`. It is marked in
  `src/lib/routing/routing.worker.ts`; `pnpm check` passes without the generated
  file, but the worker cannot execute until the Wasm build runs.
- The synchronous Wasm search blocks the worker message loop. Cancellation is
  therefore worker termination, not a cooperative cancel token. The client
  discards late results by worker identity, `requestId` and `revision`.
- The 1,048,576-cell limit is a transfer and allocation bound, not a measured
  browser budget. Search memory and frontier size are documented in the
  contract; the benchmark uses 65,536 cells.
- There is no watchdog timeout. A worker that dies without emitting an `error`
  event would leave the request pending; normal browser crash paths emit it.
  Add a watchdog when that failure is observed.
- This change does not define map geometry or a new grid format, does not move
  the renderer to Rust, and does not claim to fix GPU saturation.
- D14 must still validate travel authorization and convert cell indices to
  metres with the D04 calibration. `docs/routing-contract.md` states the
  integration contract.

## Independent advisor

An independent advisor reviewed the staged diff with a separate context and
reproduced the Rust, TypeScript, Clippy, format and parity commands. Verdict:
no blocking issue. Findings and resolutions:

- **HIGH — malformed worker message could leave the client waiting.** The
  worker now posts an explicit error when it can recover `requestId`/`revision`,
  logs only when there is no identity, and the client rejects invalid grids
  before spawning a worker. Tests cover the client rejection and the recoverable
  identity/error mapping; the worker entry itself remains unverified.
- **HIGH — worker/interop coverage was overstated.** Outcome mapping moved to
  `src/lib/routing/outcome.ts` and is tested. The report now labels the native
  wrapper tests as such and states that worker execution, wasm-bindgen glue and
  browser interop are unverified.
- **MEDIUM — `CostOverflow` and grid limits untested/undocumented.** Added tests
  for cost overflow, `GridTooLarge` and zero height. The cell limit is lowered
  to 1,048,576 and its search-memory cost is documented.
- **MEDIUM — setup cost and measurement scope.** The contract and report state
  that the millisecond range is search only; worker startup and copies are not measured.
- **MEDIUM — contract reached into D14 UI.** The busy-state sentence is now a
  D14-owned recommendation, not a mandate. The map revision reference no longer
  cites a type absent from this worktree.
- **LOW — response validation and failure identity.** `isRouteResponse` now
  rejects non-finite costs and malformed paths; `onFailure` carries the active
  `requestId` and `revision`.
- **LOW — doc contradiction and fixture scope.** The grid doc now says zero is
  traversable. The parity fixture includes a blocked cell and a zero-cost cell,
  so the zero-scaled heuristic is exercised in both languages.
- **LOW — report wording.** "All magic" corrected to 15 magic reports plus the
  pre-existing Vite parameter report.

A second independent pass confirmed both HIGH issues closed and found three
residual robustness gaps, now fixed: `postMessage` cloning failure could leave
`current` set, so the client builds an explicit payload, cancels and rethrows;
the duplicate-listener test now counts listener registrations; and response
validation now rejects `ok` responses carrying an error or `error` responses
carrying a cost/path. Wasm wrapper objects are freed explicitly after a request,
although the generated glue remains unverified.

Residual accepted debt: the fixture is duplicated across Rust/TypeScript,
`InvalidSearchState` remains an internal invariant exposed only for explicit
error reporting, and there is no worker watchdog. All are documented above.
